# Workflow
Input → inspect assets → verify facts → brand + copy → style + layout → HTML options → review → revision → approval → PNG + caption + archive.
Use the same conversation for corrections. Deliver a concrete artifact without requiring approval for routine reversible edits. HTML is the review surface; PNG is the approved delivery surface. Keep statuses explicit: draft, selected, approved, exported, published. This plugin never publishes by itself.

Project folder: brand.local.json, facts.json, review.json, review.html, assets/, designs/Product-Format-Style_vN.html, exports/Product-Format-Slide-N_vN.png, captions/Product_vN.txt. Keep all references relative where possible and bundle fonts. Avoid paths to any creator's machine. A moved project must retain its assets. All new designs enter the master gallery. Do not modify PDFs unless requested.

Verify sources before writing. A facts record should include product, source URL, retrieval date, claims with exact units, unknowns, and selected variant. Preserve contradictions; do not blend different variants. User-confirmed available colors override assumptions based on photographed colors.

Before final: inspect every slide; verify actual PNG dimensions and count, loaded images/fonts, readable text, intact logo, shared seam, no guide marks, caption has exactly five hashtags, and main review links resolve. Keep originals; collect exports by copy, not move. Report real paths and status. A successful command is not proof of good visual design.
